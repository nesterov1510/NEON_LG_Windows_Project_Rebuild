# Belet Samsung — клиент Tizen для телевизоров Samsung

Самостоятельное веб-приложение Tizen (WGT), повторяющее основные сценарии приложения Belet для Android 4.3.3 (`tm.belet.films`, versionCode 182). Это не APK, не обёртка сайта и не оригинальное приложение Belet: код написан заново, сетевые вызовы воспроизведены по разобранному Android-архиву и сверены с запросами сайта `belet.tm`.

* Пакет: `BeletFilm1`, приложение `BeletFilm1.BeletClient`, версия 0.6.1.
* Не пересекается с обычным приложением NEON `BeletTV001.Belet`: установка клиента не заменяет его.
* Tizen `required_version="4.0"` и выше (телевизоры Samsung 2018 года и новее), профиль `tv-samsung`.

## Что реализовано

| Раздел | Поведение |
| --- | --- |
| Вход | Номер телефона → `sign-in` → одноразовый код SMS/звонок → `check-code-mobile`; QR-вход (`get-qrcode` + опрос `check-qrcode`, резервный `check-qrcode-web`). Экран выбора способа кода берётся из `available-otp`. |
| Сессия | Access/refresh-токен и случайный `fingerprint` в `localStorage` (`neon_belet_samsung_session_v2`). Автообновление при 401 (`refresh-mobile`), при отказе обновления — выход на экран входа. Явный выход чистит локальные данные и вызывает `log-out`. |
| Главная | Строки `home_page` (v2, резерв v1) с горизонтальной прокруткой, hero-баннер из группы `source=header`, полоса прогресса у строки «Продолжить просмотр», подгрузка следующих страниц. |
| Разделы | `categories` и `home_page/{category_id}` с постраничной загрузкой: Фильмы, Сериалы, Спорт, Музыка, ТВ-шоу, Мультфильмы, Аниме, Документальные, Образование. |
| Поиск | Экранная клавиатура с русской и цифровой раскладкой, `POST /api/v2/search` (резерв — `search.belet.me`), подгрузка следующих страниц результатов. |
| Карточка фильма | `movie/{id}`: постер, фон, год, возраст, рейтинги КП/IMDb, жанры, страны, описание, трейлер, избранное. Для сериалов — сезоны (`seasons`) и серии (`episodes`), выбор сезона и запуск конкретной серии. |
| Плеер | HLS сначала воспроизводится через **hls.js и MSE** по схеме сайта Belet: `/api/v3/files` возвращает источники и `session_id`, приложение готовит HLS master playlist, затем загружает уровни и сегменты с веб-заголовками Belet. При недоступности MSE используется Samsung **AVPlay**, затем HTML5 `<video>`. Автоматический переход между движками и источниками, «сторож» запуска на 15 с, OSD с таймкодом и буфером, пауза/продолжение, перемотка ±10 с, возврат к карточке. Если ТВ блокирует автозапуск, показывается «Нажмите OK». |
| Прогресс | `POST /api/v3/lastWatchTime` (movie_id, season_id, watch_time, play_time, `X-Player-Session-Id`) при паузе, перемотке, выходе и каждые ~20 с; при возврате предлагается «Продолжить с …». |
| Избранное | `GET/POST/DELETE /api/v1/favorites?movieId=` и отдельный экран списка. |
| Профиль | `GET /api/v2/users/profile`: телефон, название подписки и её статус. Выход из аккаунта. |
| Устройства | При старте с сохранённой сессией и сразу после входа отправляется `POST /api/v1/users/device` с моделью телевизора из `webapis.productinfo.getModel()` — ТВ появляется в списке устройств аккаунта Belet (на телефоне). |
| Диагностика | Экран «О приложении»: проверка `beletapis.com`, `homepage.belet.me`, `film.beletapis.com`, модель телевизора, fingerprint, статус регистрации в списке устройств, состояние сессии и результат последнего воспроизведения (движок/ошибка). |

## Управление пультом

| Кнопка | Действие |
| --- | --- |
| Влево/вправо/вверх/вниз | Пространственная навигация по `.focusable`-элементам (строки, сетки, чипы, клавиатура). |
| OK / Enter | Выбор. В плеере — пауза/продолжить. |
| RETURN | Назад по истории экранов; в плеере — выход к карточке; на главной дважды — выход из приложения. |
| PLAY / PAUSE / PLAY_PAUSE | Управление воспроизведением (регистрируются через `tizen.tvinputdevice`). |
| OK после ошибки плеера | Повторный запуск: клиент заново перебирает все движки и источники. |
| REWIND / FASTFORWARD | Перемотка на 10 секунд. |
| STOP | Выход из плеера. |

## Сеть и контракт API

| Назначение | Хост | Основные вызовы |
| --- | --- | --- |
| Авторизация, профиль | `https://beletapis.com` (резерв `https://api.belet.tm`) | `/api/v1/auth/*`, `/api/v2/auth/refresh-mobile`, `/api/v2/users/profile` |
| Каталог | `https://homepage.belet.me` | `/api/v2/home_page`, `/api/v2/home_page/{id}`, `/api/v1/categories` |
| Фильмы | `https://film.beletapis.com` | `/api/v3/movie/{id}` (резерв `/api/v2/movie/{id}`), `/api/v2/seasons`, `/api/v2/episodes` (резерв `/api/v3/episodes`), `/api/v3/files/{id}`, `/api/v3/lastWatchTime`, `/api/v1/favorites`, `/api/v1/continues` |
| Поиск | `https://film-search.belet.me` | `POST /api/v2/search` (резерв `https://search.belet.me`) |
| Видео и картинки | `https://videofilm.belet.me`, `https://img.belet.me` | HLS-потоки и изображения |

Каждый запрос, как в Android-клиенте, отправляет `lang`, `fingerprint`, `app-version: 182`, `X-App-Version: 4.3.3`, `X-Platform: Android`, `X-VersionCode: 182` и `Authorization: <token>` (кроме входа и обновления). Заголовки выставляются ровно один раз: дубликаты ломают CORS-preflight.

Медиапоток использует веб-контракт сайта Belet. После `/api/v3/files/{id}` берётся `session_id`; исходные manifest-файлы запрашиваются с `Authorization` и `Fingerprint`, а HLS.js загружает master/level playlist и фрагменты собственными загрузчиками. На media-запросы передаются `X-Platform: Web`, `X-VersionCode: 17300`, `X-Player-Session-Id`, `Fingerprint` и актуальный `Authorization`; фрагменты дополнительно получают `X-Chunk-Length`, вычисленный из длительности сегментов уровня. Манифесты сводятся в Blob master playlist, как в `belet.tm`, и воспроизводятся через MSE. Перед HLS-запросами обновляется токен; HTTP 401 запускает повтор/резервный движок.

Регистрация устройства отправляет ровно то тело, что и Android-класс `DeviceBody`: `app_version`, `fingerprint`, `model`, `os_version` (версия Tizen из User-Agent), плюс заголовок `X-Device-Model`. Без `fingerprint`/`os_version` сервер Belet отвечал `HTTP 400` и телевизор не появлялся в списке устройств телефона.

Список хостов закреплён в `config.xml` через `tizen:content-security-policy`: `connect-src` покрывает `beletapis.com`, `*.beletapis.com`, `api.belet.tm` и `*.belet.me` (в том числе `videofilm.belet.me`, откуда hls.js тянет плейлисты и сегменты), `media-src https: blob:`. Телеметрия `sentry.belet.me` и `posthog.belet.me` не используется. Привилегия `avplay` объявлена отдельно — без неё `webapis.avplay` на телевизоре недоступен.

## Сборка и установка

```bash
python scripts/build_belet_samsung.py      # → samsung-belet/BeletSamsungClient-unsigned.wgt
```

В пакет входит `hls.min.js` (hls.js 1.5.20, Apache-2.0, файл `hls.LICENSE`) — он нужен для воспроизведения HLS на телевизорах, где встроенный `<video>` не умеет m3u8.

В NEON: включите Developer Mode на телевизоре, укажите IP Samsung и нажмите **«Установить Belet Samsung · Новый клиент»** — WGT уже входит в сборку и подписывается сертификатом для этого ТВ. Вручную: **«Выбрать WGT и установить»** и указать полученный файл.

## Тесты

```bash
node tests/belet_samsung_client_mock.js                       # сценарии UI на фейковом DOM и XHR
python -m pytest tests/test_belet_samsung_client.py -q        # упаковка, ES5, CSP, мок-сценарии
```

Мок-тест загружает настоящие `api.js`/`app.js`, подменяет DOM, `localStorage`, таймеры и `XMLHttpRequest`, а затем проходит вход по коду, каталог, сериалы (включая запрос сезонов и запуск первой серии), плеер на `<video>` и на AVPlay, переход на резервный источник, отчёт о прогрессе, избранное, поиск, профиль, выход, QR-вход, обновление токена при 401 и отказ обновления. Любой незапланированный запрос считается ошибкой теста.

Отдельные проверки в pytest подтверждают ES5-синтаксис `api.js`/`app.js`, отсутствие внешних скриптов, наличие всех `id`, на которые ссылается `app.js`, состав WGT, CSP с хостами Belet и совместимость CSS с движками Tizen 4–6 (без `inset` и flex-`gap`).

## Статус проверки

Логика, сетевой слой и разметка проверяются автоматическими тестами и сверяются со структурами Android-архива. Сборка 0.6.0 проверялась на телевизоре Samsung (Tizen 6.0): вход по коду и QR, главная, каталог, поиск, профиль и картинки работали. В 0.6.1 были исправлены регистрация устройства (`DeviceBody` + `X-Device-Model`), HTTP 401 на плейлистах HLS (заголовок `Authorization` в `xhrSetup`, повтор со схемой `Bearer`, обновление сессии) и загрузка серий. В текущей версии добавлено распознавание HLS по MIME/type и разбор полей источника Android. Воспроизведение и полный диапазон моделей Samsung требуют отдельной проверки на телевизоре:

* набор кодеков, DRM-потоки и запуск на разных моделях не проверялись, текущий движок и причина сбоя видны в бейдже плеера и на экране «О приложении»;
* серверы Belet отвечают `Access-Control-Allow-Origin: https://belet.tm`, поэтому теоретически встроенный браузер ТВ может заблокировать запросы из WGT. На телевизоре, где проверялся предыдущий прототип, вход и каталог открывались; при ошибке HTTP 0 экран «О приложении» покажет, какой хост недоступен;
* возможны региональные ограничения и серверные проверки `X-Device-Model`/`X-Device-Limit`;
* интерфейс и текст подписок стоит уточнить после первого запуска на ТВ.

Клиент не обходит ограничения доступа, не содержит аккаунтов, токенов и ключей из архива и не является официальным приложением Belet.
